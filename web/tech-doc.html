海外舆情检索方案生成 Agent

输入一个中文公司名,系统自动完成六步分析,生成一套可执行的海外舆情监测方案 —— 全程无需人工编写检索词。

1这个东西能干什么?

传统做法:要监测一家企业在海外的舆情,运营人员需要手动完成一系列工作——查公司的海外注册名、梳理关键词、编写检索式、找当地媒体清单、定监测频率。这项工作熟练的人也要 1-2 天,新手容易漏。

现在:你只需要在系统里输入一个中文公司名,点一下「开始生成」,系统自动跑完六个步骤,输出一整组检索方案。你可以勾选保留哪些,确认后入库,一键导出 Excel 直接交给爬虫系统执行。

2为什么用 LangChain 这种方式开发?

先打个比方

您平时用的对话式 AI(比如 DeepSeek 网页版),相当于一个「指哪打哪的实习生」——你问一句它答一句,答得不错,但它记不住多步任务,也不能自己动手调用外部工具。

而这次要做的事,是让 AI 独立完成一整条业务流水线:拆任务 → 上网查证 → 按格式产出 → 人工确认 → 入库。这需要 AI 能"按流程干活",而不是"回答问题"。LangChain 就是干这个的——它是把 AI 变成"按流程干活的员工"的标准框架。

普通对话式 AI 做不到的三件事

能力对话式 AI本次系统(LangChain)
多步流程单轮问答,上下文一长就乱六步流水线按顺序执行,每步产物传给下一步,结果可审查
调用工具不能自己上网搜索/调系统自动调用联网搜索(3 个搜索引擎),用搜索结果验证后再产出
按格式输出回答是自由文本,格式随缘强制输出固定 JSON 格式,每步经脚本校验,缺数据自动标注

具体到本项目,LangChain 解决了 4 个实际问题

① 流程编排 — 六步流水线谁先谁后、每步产物怎么传递、失败怎么处理,用 LangGraph(状态图)显式定义。类比:给 AI 画了一张「业务流程图」,它照着走,不会跳步。
✓ 解决:AI 不会漏步骤、跑偏
② 工具调用 — AI 需要"上网查证"(比如验证海外法人名是否真实存在),通过标准工具接口接入 3 个搜索供应商(一个失败自动切换另一个)。
✓ 解决:AI 能自己查资料,不靠猜
③ 结构化输出 — 强制 AI 输出固定格式(JSON),再用脚本校验字段、补默认值、缺数据记 GAP。类比:AI 填好每步的「标准表格」,填错/漏填系统会拦下来。
✓ 解决:产出的方案能直接入库、直接导出 Excel
④ 状态可恢复 — 生成过程存到本地数据库,中断了可以从断点继续,不用从头再来。
✓ 解决:生成到一半断了不白干

组件作用对应技术
六步流水线实体测绘 → 画像 → 关键词 → 检索式 → 信源 → 频次,每步「联网搜索 + AI 生成 + 脚本校验」LangGraph(编排)+ DeepSeek(生成)+ MCP 搜索池
AI 大脑按每步指令生成内容,强制 JSON 输出DeepSeek(DeepSeek 官方 JSON 模式)
联网搜索查证实体名/找属地媒体/验证域名,3 个搜索引擎自动切换MCP 标准协议(集成 Tavily / SerpAPI / Brave)
领域知识海外舆情方法论(六层关键词/双轨检索式/信源白名单等规则)skill 知识包 + 6 个分步校验脚本
API 服务对外提供 6 个接口:提交/进度/方案/勾选/入库/导出FastAPI(Python 标准 Web 框架)
安全与计费API Key 鉴权 + 用户归属校验 + 每次完整生成计费 1 单位自研鉴权/计费模块
监控全链路追踪,每步耗时/搜索/生成都可查OpenTelemetry(行业标准可观测框架)
📌 术语速查:LangChain = AI 应用开发框架(把大模型变成可编程组件);LangGraph = 其子框架(定义多步流程的状态机);MCP = 标准化的「AI 调用外部工具」协议(类比 USB 接口,统一各家搜索/数据库的接入方式);JSON = 标准数据格式(计算机之间交换数据的通用语言)。

5一句话总结

这次做的不是"一个能聊天的 AI",而是一个按流程干活的 AI 员工:输入公司名,六步流水线自动完成,产出可直接执行的舆情监测方案。LangChain 的作用,就是给 AI 装上流程、工具、格式、状态四样东西,让它从"回答问题"升级为"完成工作"。
