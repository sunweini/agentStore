海外舆情检索方案生成 Agent

输入一个中文公司名,系统自动完成六步分析,生成一套可执行的海外舆情监测方案 —— 全程无需人工编写检索词。

1为什么要开发这个 Agent?

1.1 业务背景:海外舆情监测的现状痛点

企业海外项目(矿山、冶炼、基建)风险高发,属地媒体、法律诉讼、安全事故等信息直接影响企业声誉和经营。但监测工作长期依赖人工,存在三个绕不开的问题:

痛点具体表现
① 慢人工梳理一个主体的监测方案需 1-2 天:查海外注册名、编关键词、写检索式、找属地媒体、定频率,全部手工
② 漏只用集团名检索,海外法人名、项目地名、拼写变体不进词表——当地媒体只写法人名不写母公司名,结果一场诉讼完全抓不到
③ 乱词表一放开,短缩写(15MCC)撞上同名干扰,噪音淹没运营;方案格式不统一,换个系统就作废
核心矛盾:监测方案的质量决定监测效果,而方案编制依赖高度专业的领域经验(海外法人测绘、属地信源、风险定级),经验集中在少数人手里,复制难、传承难。

1.2 为什么用 AI 解决:对话式 AI 不够,需要 Agent

您平时用的对话式 AI(DeepSeek 网页版)能"回答专业问题",但这里的工作是完成一整条流程——不是问一句答一句,而是:拆任务 → 上网查证 → 按格式产出 → 人工确认 → 入库。这需要三类对话式 AI 不具备的能力:

能力对话式 AIAI Agent(本次开发)
多步流程单轮问答,长任务上下文一长就乱六步流水线按顺序执行,每步产物传给下一步,结果可审查
调用工具不能自己上网搜索,只能"凭知识回答"(过时/编造风险)自动调用联网搜索(3 个搜索引擎),用搜索结果验证后再产出,可溯源
按格式输出回答是自由文本,格式随缘,无法直接入库强制输出标准格式,每步脚本校验,缺数据自动标注 GAP

LangChain 就是把这个"从回答问题到完成工作"的能力标准化的框架——它给 AI 装上流程编排、工具调用、格式约束、状态恢复四样东西,AI 从"实习生"变成"能独立干活的员工"。

1.3 价值:开发这一个 Agent 解决了什么

1-2天 → 6分钟方案编制时间
0漏抓海外法人/地名全进词表(分层覆盖)
标准统一格式/口径/信源规则全固化
经验资产化领域方法论沉淀为可复用知识包
  • 效率:方案编制从人工 1-2 天压缩到 6 分钟,运营人员从"编方案"转为"审方案"(勾选确认)
  • 质量:六层关键词字典(实体/地名/人名/产品/风险/排除)+ 短缩写防误报规则,解决"漏抓"与"噪音"两个老问题
  • 沉淀:监测方法论(分层词表/双轨检索式/信源白名单/频次定级)从"人脑经验"变成"系统知识包",新同事也能产出专家级方案
  • 扩展:架构支持任意监控主体(企业/项目/区域),加一个公司名就生成一套方案;后续可接爬虫调度器实现全自动监测

2这个东西能干什么?

传统做法:运营人员手动完成——查海外注册名、梳理关键词、编写检索式、找当地媒体清单、定监测频率。熟练的人 1-2 天,新手容易漏。

现在:输入一个中文公司名,点「开始生成」,系统自动跑完六个步骤,输出一整组检索方案。勾选保留哪些,确认后入库,一键导出 Excel 直接交给爬虫系统执行。

3技术是怎么实现的?

本节给关心技术细节的同事看;核心结论:不是"接了个聊天机器人",而是"搭了一条自动化流水线",每个环节都有校验和兜底。

3.1 总体架构

用户输入公司名→ API 网关
鉴权 · 计费→ 六步流水线
LangGraph 状态机→ 方案组
JSON 入库→ 勾选确认→ Excel 导出

3.2 六步流水线详解(每步:联网搜索 → AI 生成 → 脚本校验)

步骤做什么为什么这样做(对应业务价值)
① 实体测绘识别母公司/海外法人(按语区分组)/拼写变体/同名干扰源,联网验证召回率命脉:当地媒体只写法人和地名,必须全量进词表
② 主体画像判定角色(承包商/业主),建立 direct/indirect/context 三级相关度口径承包商视角时,业主负面是"传导风险"不算自身负面——统计口径防虚高
③ 关键词字典A实体/B地名/C人名/D产品/R风险/X排除 六层词表,短缩写强制 context_guard分层=不同检索行为;guard 防 15MCC 撞上 MCC 中冶系等噪音
④ 双轨检索式按国别×项目群分组,每轨生成布尔+Google 两套语法两套语法取反/括号规则不同,混用会静默失效,必须双版本
⑤ 属地信源每轨配属地媒体/判例库/政府/NGO 域名白名单,联网验证活性国际大媒体只报大事,早期信号在属地媒体——白名单决定信噪比
⑥ 频次定级按风险信号定频次(快讯/日/周/双周/月)+ 风险等级(4 级)人员安全组走小时级快讯管道;诉讼升级自动提频

3.3 质量保障:三层校验,AI 不会"乱来"

① 输入校验 — 每步 AI 输出强制 JSON 格式,由分步脚本校验字段/补默认值/缺数据记 GAP(如"俄语关键词未覆盖"),格式错自动重试 2 次。
✓ 保证:AI 自由发挥但不越界,产出可入库
② 领域规则 — 领域方法论(六层词表/双轨语法/信源类型/频次信号)固化在知识包,AI 按规则产出,不靠临场发挥。
✓ 保证:专业质量不依赖 AI 聪明程度
③ 人工确认 — 生成结果先落草稿,人工勾选确认后才入库;已入库方案冻结,不可随意改动。
✓ 保证:AI 产出永远有人把关

3.4 组件清单与对应技术

组件作用对应技术
六步流水线流程编排,每步产物传递,中断可续跑LangGraph(状态机)
AI 大脑按每步指令生成内容,强制 JSON 输出DeepSeek(JSON 模式)
联网搜索查证实体/找属地媒体/验证域名,3 引擎自动切换MCP 协议(集成 Tavily/SerpAPI/Brave)
领域知识舆情方法论 + 六步格式契约skill 知识包 + 6 个校验脚本
API 服务提交/进度/方案/勾选/入库/导出 6 接口FastAPI
安全与计费API Key 鉴权 + 用户归属校验 + 每次生成计费自研鉴权/计费模块
监控全链路追踪,每步耗时/搜索/生成可查OpenTelemetry(行业标准)

3.5 可靠性设计

  • 搜索容错:3 个搜索引擎(一个失败自动切换),不会因单点失败中断
  • 中断续跑:生成进度持久化,中断后从断点继续,不白跑
  • 错误可查:每步状态(待执行/进行中/完成/失败)实时可见,失败原因留痕
  • 防刷计费:API Key 鉴权 + 并发上限,防止资源滥用
📌 术语速查:LangChain = AI 应用开发框架(把大模型变成可编程组件);LangGraph = 其子框架(定义多步流程的状态机);MCP = 标准化的「AI 调用外部工具」协议(类比 USB 接口,统一各搜索/数据库接入方式);JSON = 标准数据格式(计算机交换数据的通用语言)。

5一句话总结

这次做的不是"一个能聊天的 AI",而是一个按流程干活的 AI 员工:输入公司名,六步流水线自动完成,产出可直接执行的舆情监测方案。LangChain 的作用,就是给 AI 装上流程、工具、格式、状态四样东西,让它从"回答问题"升级为"完成工作"。它解决的不只是效率问题,更是把监测方法论沉淀为系统能力——人走了,经验还在。
