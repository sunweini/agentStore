# 频次与风险定级

## 定级不是拍脑袋

频次和风险等级要能说出依据。给客户交清单时，运营注里必须写明"为什么这组是日级"，否则后续没人敢调整，清单会僵死。

---

## 风险等级四档

| 等级 | 判定标准 |
|---|---|
| **critical** | 人员死亡/失踪、大规模停工、最高审级诉讼、所在区域武装冲突、涉在场人员安全 |
| **high** | 执法处罚、群体性指控、局部罢工、诉讼立案、NGO 或国际媒体点名报告 |
| **medium** | 争议性报道、单点纠纷、负面倾向但未成事件 |
| **low / info** | 中性披露、行业动态、正面报道 |

**关键判据：是否涉及在场人员安全。** 只要监测主体有人员在该区域，且该区域有武装冲突、治安恶化、绑架案例，这一组就是 critical，不论目前是否已出事。预警的意义在于出事之前。

---

## 频次五档

| 频次 | 适用场景 |
|---|---|
| **快讯/小时级** | critical 且涉人员安全的组。命中即推送，不等轮询 |
| **日级** | 进行中的司法程序、政治敏感期、已发酵的重大事件、集团层负面精准轨 |
| **周级** | 常规核心项目组（有实质业务、风险中等） |
| **双周级** | 次要项目、新签未开工项目 |
| **月级** | 轻扫组、待证项目、低风险区域 |

### 快讯管道要单独建

critical 涉人员安全的组，**不要混在常规轮询里**。做法是：把风险词表里的人身安全词（死亡、袭击、绑架、伤亡等，分语种）单独抽出来，配上地名键，做成独立的高频快讯式，命中直接推送给应急联系人。

常规精准轨周级跑就行，快讯管道小时级跑。两者并行，职责分开。

## 提频触发信号

以下情况出现时，把相关组的频次上调一档，并在运营注里记明原因和预计持续时间：

| 信号 | 说明 |
|---|---|
| **所在国大选年/选举周期** | 涉外资的环境、劳资议题极易被政治化，成为竞选素材 |
| **项目高曝光节点** | 投产、复产、剪彩、重大签约。正负面报道都会集中，且负面在此时杀伤力最大 |
| **诉讼进入更高审级** | 从地方法院升到最高法院，意味着议题级别跃迁，会引来国际关注 |
| **议题外溢** | 事件出现在国际媒体、学术论文、维基百科条目、纪录片中——说明已脱离属地范畴 |
| **当地治安/战事恶化** | 直接关系在场人员安全 |
| **NGO 或国际律所介入** | 跨境法律动员启动，后续会有持续输出 |
| **同行业同区域出事** | 监管会加强检查，容易被连带波及 |

### 降频信号

也要允许降频，否则清单只增不减最终跑不动：

- 事件结案且无后续（连续 3 个月零命中）
- 项目退出/移交
- 经核实并非监测主体项目（承包关系证伪）

---

## 承包关系核实：一个必须做的前置动作

**定级之前要先确认项目到底是不是监测主体的。**

常见错误是把同区域、同行业的其他中资企业项目算进来。后果很严重：负面指标虚高，真实风险信号被稀释，客户看到一堆与自己无关的负面后会失去对系统的信任。

核实方法：
- 查中标公告、项目官网、当地政府发布
- 交叉验证至少两个来源
- 无法确认的，登记为 GAP，放进轻扫组低频观察，**不进主线统计**

已证伪的项目要明确写进交付物（"某某项目总包方实为 XX 公司，非监测主体，其舆情不得计入客户指标"），防止下一轮又被加回来。

---

## 相关度分层与统计口径

这条最容易出错，单独强调：

**统计客户负面时，direct / indirect / context 三层不能直接合计。**

- `direct` = 监测主体自身负面 → 计入客户指标
- `indirect` = 关联实体/业主负面 → 传导风险，单独出数
- `context` = 同区域行业性负面 → 纳入监测，不计入客户指标

在统计 sheet 里要写明这个口径，并给出"若只统计 direct+indirect 负面，核心议题为 X 和 Y"这样的结论句，帮运营和管理层看懂真实风险画像。
