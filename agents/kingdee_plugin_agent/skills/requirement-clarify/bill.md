# 单据插件需求澄清问题模板(bill)

用法:一次一问,多选优先;提问前先查元数据(KingdeeApiClient),把真实操作/字段列给用户选,
不让用户手打 FormId。问题按轮次推进,上限 10 轮;每问一答记入 decisions,用户未说默认值记入 assumptions。

覆盖:触发操作 / 校验字段 / 拦截方式 / 联动单据 / 异常处理。

## 1. 触发操作(必须确认)
- 插件挂在哪个单据的哪个操作上?(如:采购单-审核 / 保存 / 提交 / 删除)
- 选项来自元数据该单据的可用操作列表;一次插件建议只挂一个操作,多操作需求拆多个子任务。

## 2. 触发时机
- 操作执行前(校验/拦截类)还是操作执行后(联动/回写类)?
- 若涉及审核流:在审核前、审核通过后还是反审核时触发?

## 3. 校验字段(必须确认)
- 要校验哪些字段?选项来自元数据真实字段(如:数量 FQty / 库存组织 / 仓库 / 单价)。
- 每个字段的校验规则:范围约束、必填、与单据其他字段的联动约束。

## 4. 拦截方式(必须确认)
- 校验不通过时怎么处理?
  - 硬拦截:抛异常,操作不提交,界面提示用户
  - 软拦截:仅提示/标记,不阻止提交
- 拦截提示文案要写什么?

## 5. 联动单据(按需确认)
- 校验/操作是否涉及其他单据(如:校验库存需读库存单、生成下游单据)?
- 若联动:目标单据、写入字段、是否允许跨组织。

## 6. 异常处理(必须确认)
- 插件运行异常(元数据/依赖服务不可用)时:回滚当前操作、记日志继续,还是通知处理人?
- 校验不通过是否需要记审计日志或通知审批人?
