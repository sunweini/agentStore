# 列表插件需求澄清问题模板(list)

用法:一次一问,多选优先;提问前先查元数据(KingdeeApiClient),把真实字段/操作列给用户选,
不让用户手打 FormId。问题按轮次推进,上限 10 轮;每问一答记入 decisions,用户未说默认值记入 assumptions。

覆盖:列表字段 / 操作按钮 / 过滤条件。

## 1. 列表单据(必须确认)
- 插件挂在哪个单据的列表上?(选项来自元数据 list_formids)
- 是主列表(打开即见)还是子列表(嵌入其他单据,如分录)?

## 2. 列表字段(必须确认)
- 列表需要展示/管控哪些字段?(选项来自元数据 get_form_fields,如:单据编号/状态/数量/金额)
- 字段权限:哪些列只读、哪些列可编辑、哪些列隐藏?

## 3. 操作按钮(必须确认)
- 列表操作栏要加/改哪些按钮?(选项来自元数据 get_operations,如:审核/提交/批量删除)
- 按钮可用条件(选中行状态过滤:如仅"已提交"行可选)、批量选择时的逐行处理语义。

## 4. 过滤条件(按需确认)
- 列表默认过滤条件:按组织/状态/时间过滤?
- 过滤参数来源:界面输入、调用方传入,还是固定默认值?

## 5. 批量处理异常(必须确认)
- 批量操作部分失败时:逐行反馈还是整体回滚?失败行如何提示、成功行是否保留?
- 是否需要记录批量操作日志(操作人/时间/处理行数)?
