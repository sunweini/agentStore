# 金蝶插件需求澄清方法论(requirement-clarify)

配合 w1 需求澄清阶段使用。系统提示已注入本 skill 摘要,LLM 需要完整问题模板时
调用 `load_skill("requirement-clarify")` 获取本文与三套类型模板。

## 核心规则

1. **一次一问**:每次只问一个问题,问题按轮次推进,上限 10 轮(MAX_ROUNDS)。
2. **多选优先**:给用户可选项(来自元数据真实数据),不让用户手打 FormId。
3. **元数据驱动**:提问前先查元数据(KingdeeApiClient),把真实操作/字段列给用户选。
4. **决策 + 假设记录**:每问一答记入 `spec.decisions`;用户未说默认值记入
   `spec.assumptions`;确认摘要必须列出决策 + 假设。
5. **问题收敛**:一次插件建议只挂一个操作,多操作需求拆多个子任务。

## 类型模板(按插件类型取用)

| 类型 | 模板文件 | 覆盖 |
|---|---|---|
| 单据插件 | [bill.md](bill.md) | 触发操作/触发时机/校验字段/拦截方式/联动单据/异常处理 |
| 服务插件 | [service.md](service.md) | 服务入口/调用方式/事务边界/异常回滚/调用方上下文/返回与提示 |
| 列表插件 | [list.md](list.md) | 列表单据/列表字段/操作按钮/过滤条件/批量处理异常 |
