# 服务插件需求澄清问题模板(service)

用法:一次一问,多选优先;提问前先查元数据(KingdeeApiClient),把真实服务/字段列给用户选,
不让用户手打 FormId。问题按轮次推进,上限 10 轮;每问一答记入 decisions,用户未说默认值记入 assumptions。

覆盖:服务入口 / 事务边界 / 异常回滚 / 调用方。

## 1. 服务入口(必须确认)
- 服务挂在哪张单据/业务对象上?服务名/类名是什么?(选项来自元数据 list_formids 与操作列表)
- 服务暴露哪些方法?每个方法的入参、返回值契约。

## 2. 调用方式(必须确认)
- 服务由谁调用:单据操作内调用、列表操作调用、还是外部接口直接调用?
- 调用时机:保存前/保存后/审核时?是否需要幂等控制(重复调用不重复生效)?

## 3. 事务边界(必须确认)
- 服务内涉及几步写操作?事务从哪一步开始、到哪一步提交?
- 是否跨单据写入(联动更新其他单据)?事务超时与并发(锁)策略。

## 4. 异常回滚(必须确认)
- 服务执行失败时:整体回滚、部分回滚+补偿,还是仅记录日志继续?
- 业务校验失败与系统异常(网络/元数据不可用)是否区分处理?

## 5. 调用方上下文(按需确认)
- 调用方需要传哪些上下文:组织/部门、操作人、业务日期?
- 是否需要权限校验(哪些角色/组织可用本服务)?

## 6. 返回与提示(必须确认)
- 成功/失败的返回结构(成功码+数据 / 失败码+消息)由谁定义?
- 失败时的界面提示文案与审计日志要求。
