# 金蝶 BOS 插件编译修复方法论(compile-fixer)

配合 w5 编译修复阶段使用。系统提示已注入本 skill 摘要,LLM 需要完整修复方法论
与经验库检索指引时调用 `load_skill("compile-fixer")` 获取本文与
references/errors.md(纯方法论;具体错误映射不在 skill 内,走经验库检索)。

## 目标

把 Plugin.cs 提交容器编译;失败则**逐轮定位根因 → 修复 → 重编**,至多 5 轮
(MAX_COMPILE_ROUNDS)。编译通过 → compile_errors 清空 + DONE;5 轮仍失败 →
上报编译超限(evidence 含最后错误列表),退回 w3/w4 或问用户。

## 输入

- `code`:当前 Plugin.cs(每轮改写后整体写回重编)
- `compile_errors`:本轮错误列表(每条含 code/message;经验库命中时带
  experience 附注,格式 "[错误码] 错误信息 修复:修法")
- 经验库:按错误码+错误信息语义检索的修复建议

## 修复流程(每轮)

1. **错误分类**:逐条把错误归入 `references/errors.md` 的分析维度
   (缺引用与命名空间/签名与基类不匹配/拼写与作用域/语法与占位符残留),
   先分类再动手 —— 分类错了修法就错了。
2. **根因定位**:按 `references/errors.md` 的根因分析方法 —— 区分表象与根因
   (级联错误找源头,签名错误是级联源)、阻断性优先;具体根因链与修法从
   compile_errors 的 experience 附注(经验库检索结果)取,不凭记忆猜。
3. **经验库检索策略**:按 错误码 + 错误信息语义 检索;
   - 命中 → 直接按建议修复并**自核**(建议可能与当前代码上下文不符);
   - 未命中 → 按金蝶 BOS API 规范自行修复;
   - 标注 confidence 的经验条目仅作参考、须自核后才采用。
4. **修复优先级**:先修阻断性错误(缺 using/签名不匹配 —— 往往一条修复消掉
   一片同类错误),再修单点错误(拼写/成员名);每轮只处理本轮错误,
   **不重构无关逻辑**,防级联错误误判。
5. **写回重编**:修复后把新代码**整体写回 Plugin.cs**(store.write),
   交由编译容器重编;循环至多 5 轮。

## 输出契约

- 每轮:修复后的完整代码写回 Plugin.cs,交由编译容器重编。
- 5 轮仍失败 → 上报编译超限(evidence 含最后错误列表),退回 w3/w4 或问用户。
- **禁止**:伪造编译成功;为消除错误直接删除功能代码;把"经验未命中"当成
  拒绝修复的理由。

## 踩坑与纪律

- **防重复提交**:每轮必须真实改写(代码与上一轮不同)才提交重编;
  原样重提交只会烧掉轮次。LLM 未改写时上层会原样重编,轮次上限兜底 ——
  但每轮都该尽力给出真实修改。
- **级联错误**:一处签名错误会引发一串下游错误(方法调不到 → 成员不存在 × N);
  优先修根因(签名),不要逐个去"修"下游表象。
- **经验库是建议不是圣旨**:经验附注可能与当前代码不匹配,自核后采用;
  confidence 低的条目尤其要核实上下文。
- **编译服务不可用 ≠ 修复失败**:服务不可用(BLOCKED)不计轮次、不扣预算,
  不要为了"过编译"去删功能代码。
- **删除功能代码是最后手段且要上报**:宁可编译超限退回 w3,也不静默删功能。
