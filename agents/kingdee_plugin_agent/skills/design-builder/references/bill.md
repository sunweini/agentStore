# 单据/表单插件设计检查清单(bill,基类 AbstractBillPlugIn)

用法:逐项检查,**每项都要在设计文档中给出明确结论**("不涉及"也是结论)。
字段/操作选项一律来自元数据 get_form_fields / get_operations,禁止编造。

## 1. 触发操作与时机(必须)
- 插件挂载在哪个单据的哪个操作上(如:采购单-审核/保存/提交/删除)?
- 触发时机:OnLoad 初始化 / AfterDoOperation 操作后联动 / 操作前校验(拦截类)。
- **只挂 w1 确认的单一操作**;多操作需求由 w1 拆分的多个子任务承接,本设计不追加。
- 检查自问:设计文档是否写明了 操作 + 时机 二要素?若涉及审核流,是否写明
  审核前/审核通过后/反审核时?

## 2. 控件绑定与字段映射(必须)
- 要操作的真实控件字段(来自元数据 get_form_fields,如 FQty/库存组织)。
- 每个字段的**读写方向**:读源字段 → 计算 → 写目标字段,链条写清。
- 控件状态变更:可见/可编辑/禁用,哪些条件下变更。
- 检查自问:每个出现的字段是否能在元数据中查到?读写方向是否无歧义
  (同一字段既读又写时要写明时序)?

## 3. 拦截方式(必须)
- 校验不通过走**硬拦截**(抛异常,操作不提交,界面提示)还是**软拦截**(仅提示/标记,
  不阻止提交)?
- **拦截提示文案必须写进设计**(w3 照抄、w4 对照审查的依据)。
- 检查自问:文案是否具体到用户能看懂(含字段名/阈值),而不是"数据不合法"?

## 4. 联动单据(按需)
- 是否读写其他单据(读库存单校验、生成下游单据等)?
- 若联动:目标 FormId、写入字段、是否允许跨组织、跨组织权限如何取。
- 检查自问:目标单据 FormId 是否真实(来自元数据)?跨组织读写是否已确认组织范围?

## 5. 异常处理骨架(必须)
- 插件运行异常(元数据/依赖服务不可用)时的策略:
  - 回滚当前操作 / 记日志继续 / 通知审批人 —— 明确写一种主策略;
  - try/catch 边界在哪(整个事件方法、还是单段业务逻辑);
  - 日志记录点与级别;是否通知审批人及其时机。
- 检查自问:异常骨架是否与触发操作语义一致(操作前校验失败 = 不提交;
  操作后联动失败 = 回滚还是补偿)?

## 6. 验收自检(完成设计时)
- 设计是否满足 w1 确认的**每条**决策与假设(逐条对照,列对应小节)?
- 是否出现 w1 未确认的新业务规则(出现 = 退回 w1 或标进边界与假设)?
